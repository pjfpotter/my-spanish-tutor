## Why

A teacher sets a speaking test by choosing the questions, and the questions often come from different sentence builders: a Year 8 test may ask about films, free time, clothes, a holiday and a bedroom, and each of those has its own sheet. Two builders can also answer one question, or one builder can serve two questions (a past-tense half and a present-tense half of the same sheet, say). The v1 requirements already say "a course SHALL support one or more sentence builders" and "each question SHALL name the sentence builder whose chunks answer it" (`teacher-course-setup`, `answer-writing-coach`), but the build never did it. A course stores one sheet and one interpretation, so a second builder had no place to go. The change `testing-course-five-builders` worked around this by merging five builders into one sheet with prefixed keys, which only works from a developer script, loses each sheet's own layout and makes teacher upload impossible. This change builds what the spec says, and settles the rule: a question has at most one builder, and a builder may serve several questions.

## What Changes

- A course holds a list of sentence builders (each one a re-typeset sheet plus its checked interpretation), not a single sheet. **BREAKING** for the course file format and the `courses` table (see Impact).
- Each question names at most one of the course's builders. Several questions may name the same builder. A question that names none shows "no sentence builder for this question yet", as an unmatched question does today. It is never answered from another question's builder.
- The write screen for a question shows only its builder's sheet, as that builder was uploaded. There is no merging, no key prefixes and no filtering of tables by block.
- A question that names a builder is also linked, by a stored pointer, to one of that builder's own questions (a section of the sheet), so a builder with a present half and a past half can serve two questions. The seed fills the link in when the question's text equals a builder question's text, accepts an explicit link in the course file when the wording differs, and stops with a list of the builder's questions when a builder has several questions and nothing matches. A builder with one question or none needs no link. Nothing is guessed at run time.
- The course file (seed) lists its builders and each question's builder. A course needs at least one builder to be created. A question without a builder is listed as a notice when seeding and publishing, and it does not block them.
- Existing courses are carried over by a migration with no change a student can see: a course's sheet becomes its one builder, and each question that matched a sheet question by text is assigned to it and linked to that sheet question.
- The testing course `PRBA7K3M` is rebuilt as five real builders with one question each. The merge code and the block filtering on the write screen from `testing-course-five-builders` are removed.
- Each builder carries its own calibration (frame starters and justifiers, features, tenses), because those are phrases from that sheet. The course keeps only what spans the whole test (the targets, and the fallback for a question with no builder). An answer's value, the coach and the memorise practice text read the calibration of the question's builder.
- Each builder is uploaded and interpreted on its own, so one model call per builder upload (as the teacher-flow spec already says), and the cache is per document.

## Capabilities

### New Capabilities
- `question-builder-assignment`: how a course holds several sentence builders, how a question is assigned at most one, how one builder serves several questions, what a question with none does, and what the seed, status and publish checks report.

### Modified Capabilities
- `teacher-course-setup`: "More than one sentence builder" is restated (a question names at most one builder; builders are optional per question; shared builders allowed), and the draft check lists questions that have no builder. Defined in the unarchived change `ks3-spanish-speaking-tutor-v1`, so the delta is stated here as a new requirement under the new capability name, as `question-sheet-match-and-open-testing` did.
- `answer-writing-coach`: "Question's own sentence builder" now reads from the question's assigned builder and no longer matches text on every request to show one. Same treatment as above.
- `question-sheet-match`: its rule "a question with no match has no sentence builder" becomes "a question with no assigned builder has none"; the text match now only fills in a stored link to a builder question when the course is seeded, and the stored link selects the builder question inside the assigned builder. Defined in the unarchived change `question-sheet-match-and-open-testing`.

## Impact

- **Code:** `lib/course/schema.ts` (`Course.builders`, `Question.builder`, validation), `lib/course/seed-db.ts`, `lib/course/status.ts` (draft checks and the question-without-builder notice), `lib/progress/writing-store.ts` (load the question's builder, build the engine for it, sign-off against it), `app/phases/write/page.tsx` and `SheetWrite.tsx`, `lib/sheets/question-match.ts` (match within the assigned builder), `scripts/seed.mjs`, `scripts/build-audio.mjs`, `scripts/price-course.mjs`, `lib/db/dev-db.ts`, `lib/course/testing-course*.ts` (assemble five builders, no merge). Removed: `lib/sheets/merge.ts` and its test, the `blocks`-based table filter in `WriteSheet.tsx`.
- **Database:** a new migration adds a table of builders per course and a nullable builder reference and a nullable builder-question link on each question, backfills both from the existing `courses.sheet` and `courses.interpretation`, and leaves those two columns in place and unread for one release (a later change drops them). No student data is touched. Saved selections need no migration (design D4).
- **Data and docs:** `docs/user-testing.md`, `docs/technical-documentation.md`, and the `testing-course-five-builders` change (its merge decisions are superseded; mark them when this change is applied). The teacher-derived testing course data stays local-only and gitignored, as decided.
- **Out of scope:** a teacher-facing upload page (version one stays developer-run through the seed scripts, as the setup spec already says), a teacher library of sentence builders reused across courses (a later version; the data model here keeps a builder a self-contained row so a library can reference it later without reshaping it), a teacher control to reassign questions by hand, a model suggesting the link when a sheet is uploaded (a later increment, with the teacher upload page and the library), giving one question two builders, and changes to the engine's rules for polarity, pairs or sign-off.
